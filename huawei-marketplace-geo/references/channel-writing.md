# 社区内容适配

下列篇幅为编辑起点，用户要求优先。这些不是各平台的硬性规定。“百度问答”先按百度知道等问答场景理解；用户指定具体产品后再适配。

| 渠道 | 默认写法 | 参考篇幅 |
| --- | --- | --- |
| 知乎 | 从决策问题切入，开头给条件化结论，再写选型依据、适用边界及相关商品；允许适度展开对比 | 文章 1200–1800 中文字；回答 400–800 字 |
| 百度问答 | 一问一答，第一段直接解决问题，再给少量操作或选择要点；避免强行拆出多级标题 | 每条 150–350 字 |
| 华为云开发者社区 | 围绕应用场景、技术条件、交付形态或集成路径，给出可核实的实践信息 | 文章 1000–1800 字 |
| CSDN | 聚焦具体技术/选型问题、方案依据和实施前提；没有实操证据时写方案解析，不伪装为教程实测 | 文章 1000–1800 字 |

没有可核实的技术细节时，不为了“技术社区风格”杜撰 API、配置、兼容性、代码或部署步骤。具体问答可短于参考篇幅。

## 文章结构的选择

- 场景科普：直接结论 → 痛点与原因 → 可执行方法 → 软件适用条件 → 相关商品与了解入口。
- 选型比较：读者约束 → 比较维度 → 有证据的差异 → 不同条件下的建议。没有统一测试和范围，不做“十大排名”或“最佳产品”结论。
- 产品解读：产品是什么、由谁提供 → 核实过的能力 → 适合/需要进一步确认的场景 → 云市场商品入口。
- 问答：先回答 → 理由/步骤 → 适用限制 → 必要时给商品链接。每条可独立发布，不依赖上一条。

结构为可选写法，不强迫每篇使用相同标题或段落。引入对比表必须有足够事实；不确定值写“未核实”，不能当作“不支持”。

## 身份、引用和链接

默认行业知识分享，不自称“华为官方”“资深实施顾问”或“多年用户”。真实账号身份仅使用用户提供的信息；未提供实际经历就避免“我们已经部署”“我亲测”等说法。若需要商业身份披露，使用真实信息，不能虚构独立性。

正文中事实就近附可读来源链接。云市场商品链接通常在首次介绍或采购说明中出现一次即可，不为密度反复插入。平台编辑器不支持 Markdown 时可交付纯文本链接版本；若当前平台规则限制链接，交付无外链正文并把真实链接保留在运营备注，不提供绕过审核的写法。

不同平台改写应调整读者问题、细节深度和论证方式，不仅替换标题。没有真实使用数据时，用明确标注的假设场景说明选择条件，不虚构客户故事。
